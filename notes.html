게임이 안 알려주는 계산식

전부 설치된 APK에서 직접 확인한 것입니다. 마스터 데이터는 Addressables 번들에서, 계산식은 libil2cpp.so 를 디스어셈블해서 읽었습니다. 추측이 섞인 곳은 그렇다고 적어 뒀습니다.

1평판

요구 평판은 부호에 따라 방향이 반대입니다. 양수는 «그 값 이상»이라야 뜨는 하한이고, 음수는 «그 값 이하»여야 뜨는 상한입니다. 그래서 선행 체인을 하나로 합칠 수 없어, 퀘스트 색인에서는 ▲ 한 번은 올려야 하는 평판과 ▼ 한 번은 내려가야 하는 평판을 따로 계산합니다.

평판이 오르다 멈추는 이유

퀘스트 레벨 = master.level + Min(addLevel, master.maxAddLevel) 평판 상한 = 5 × (퀘스트 레벨 − TownMaster.maxReputationLevel + 1) // 최소 5 if (평판 상한 >= 현재 평판) 현재 평판 += master.reputation // 최대 99

낮은 레벨 퀘스트를 아무리 반복해도 평판이 어느 선에서 멈추는 이유입니다. 천장이 5 단위로 올라갑니다.

Town.MaxReputation · Town.ApplyReputationChange

2게시판에 뜨는 조건

등장 주기는 questSpawnInterval 입니다. 값 99는 코드 상수 QUEST_SPAWN_INTERVAL_ONLY_ONCE 와 같아 1회성을 뜻하고, 그 외 값은 클리어 뒤 재등장까지의 대기 일수로 쓰입니다. 게시된 퀘스트는 deadline 이 지나면 사라집니다.

«한 칸당 몫»은 확률이 아닙니다. 같은 평판대에서 함께 후보가 되는 퀘스트들과 questFrequency 를 나눈 비율입니다 — 게시판이 한 칸을 뽑을 때 이 퀘스트일 확률이지, 하루에 뜰 확률이 아닙니다. 1회성 퀘스트를 깰수록 경쟁 대상이 줄어 실제로는 표시값보다 좋아집니다.

하루에 몇 칸이 뽑히는지는 확정하지 못했습니다. 게시판 상한은 GameSettings.TownAverageQuestCount 이고 Town.GetCanAcceptedQuests() 가 목록 길이가 이 값에 닿을 때까지 채웁니다. 그런데 이 값은 실행 중 어떤 플래그에 따라 100 또는 30 으로 갈립니다. 화면에 보이는 개수와도 맞지 않아, 지어낸 «슬롯 수» 입력은 없앴습니다.

3금고 — 발견과 해제

살아 있는 파티원을 차례로 굴려 한 명만 통과하면 성공입니다. 발견과 해제 두 판정을 모두 넘겨야 물건을 얻고, 해제 난이도가 0이면 해제 판정은 건너뜁니다.

목표 = 퀘스트 레벨 + 금고값(발견값 또는 해제 난이도) 내 값 = 2d6(10 이상이면 다시 굴려 더함) + 도적 직업레벨 + 리더 보너스 + 통찰력/3 성공 = 내 값 >= 목표 + 2d6
함정이 둘 있습니다.
· 통찰력 보너스는 «도적레벨 + 리더보너스»가 1 이상일 때만 붙습니다. 도적을 안 키운 파티원은 통찰이 아무리 높아도 0으로 굴립니다.
· 첫 2d6이 1+1이면 −100(대실패) 입니다. 1/36은 어떤 능력치로도 못 막습니다 — 한 명 기준 천장이 97.22% 입니다.

리더 한 명에게만 붙습니다. 통찰이 높은데 도적 레벨이 없는 파티원을 리더로 두면, 그 사람의 통찰이 판정에 살아납니다.

사실상 확정을 만드는 조건

도적레벨 + 리더보너스 + 통찰력/3 >= 퀘스트 레벨 + 금고값 + 9

이걸 채운 캐릭터는 대실패(1/36)를 빼고 확정입니다. 두 명이 채우면 판정당 실패가 1/1296이라 사실상 100%입니다.

5강화 — 추가 공격과 전체 공격

두 옵션은 마스터 데이터에 없습니다. 강화(craft)가 굴립니다. 그리고 결정적인 조건이 있습니다 — 한 번에 5단계 이상 강화될 때만 도는 블록 안에만 들어 있습니다.

옵션일반 무기마법 무기
추가 공격5%15%
후열 포함15%25%
전체 공격5%15%
후열 포함과 전체 공격은 추가 공격이 먼저 붙어야만 굴립니다. 추가 공격 판정에 실패하면 두 줄을 통째로 건너뜁니다.

상점에서 살 때 붙는 등급

if RandSuccess100(20) craft = 1 // 20% if RandSuccess100(5) craft = 2 // 5% if RandSuccess100(1) craft = 3 // 1% if RandSuccess(1,1000) craft = Rand(3,6) // 0.1% → +3·+4·+5 RunCraft(craft)

+5로 나올 확률이 0.1% × ⅓ = 약 1/3000 입니다. 곱하면 상점 무기에 추가 공격이 붙을 확률은 약 1/60,000, 전체 공격은 약 1/1,200,000 입니다. 돈을 아무리 모아도 상점으로는 사실상 불가능합니다.

대장간에서 다이아로 강화할 때

상점과는 완전히 다른 사다리입니다. 그리고 시작점이 «대장간 레벨 − 장비 레벨» 이라, 낮은 레벨 장비일수록 한 번에 훨씬 많이 굴려집니다.

n = 대장간 레벨 − 장비 레벨 p = 50 while (RandSuccess(p)) { n += 1; p -= 5 } // 50% → 45% → 40% → … craftIndex = clamp(n + 1, 3, 15) RunCraft(craftIndex)

최소 3단계는 보장되고, 첫 성공이 50%라 잘 늘어납니다. 대장간 29 기준으로 다이아 한 번에 붙을 확률입니다.

다이아 강화가 상점보다 최소 수백 배 유리합니다. 다만 «전체 공격»은 5단계 블록이 딱 한 번만 돌기 때문에 5%×5% = 0.25% 가 천장입니다 — 장비 레벨을 낮춰도 더 오르지 않습니다. 마법 무기라면 15%×15% = 2.25% 로 아홉 배가 됩니다.

활만 예외입니다

강화 단계마다 도는 5% 관문을 통과하면, Weapon.Kind.Bow 는 5단계 조건 없이 추가 공격이 확정으로 붙습니다.

현실적인 길

제작등급 5 이상으로 떨어지는 드랍은 전체 데이터에 10종뿐입니다 — 도감의 «+5강 이상 드랍» 태그로 걸러집니다. 가장 높은 건 좀비 워리어의 녹슨 검(+9) 인데 Lv2 무기라 실전성은 없습니다.

그보다 두 옵션이 처음부터 박혀 있는 무기가 39종 있고, 거의 전부 퀘스트 금고에서 나옵니다. 도감 아이템 탭의 «전체 공격»(24) / «추가 공격»(15) 체크박스로 찾으세요.

마법 속성은 강화로 못 붙입니다. Enhancement.Kind.IsMagic(254) 가 enum에 있지만 Weapon.Craft 가 그걸 만드는 자리는 없습니다(생성 지점 28곳 전수 확인). 마스터 데이터의 isMagic 플래그가 유일한 경로라, 마법 속성 무기는 처음부터 그런 것을 구해야 합니다.

은퇴 — 골드와 경험치가 여기서 나온다

은퇴시킨 용병은 사라지지 않고 둘을 계속 벌어 줍니다. 은퇴 정원은 숙소 레벨 × 5 입니다.

① 경험치 보너스

보너스% = min( 조건을 통과한 은퇴자 수 × 5, 100 ) 조건: 은퇴자의 최고 직업 레벨 > 경험치를 받는 캐릭터의 레벨

스무 명이면 +100% 로 상한에 닿습니다. 그 위로는 아무 소용이 없습니다 — 다만 «내 레벨보다 높은» 은퇴자여야 세어지므로, 주력이 성장할수록 조건을 통과하는 인원이 줄어듭니다. 모험 경험치(AddAdventureExp)에 붙습니다.

② 광산 골드

광산 레벨 = 은퇴자를 최고 직업 레벨 순으로 상위 20명만 골라 그 합을 계단에 대입 계단: 5, 15, 30, 50, 75, 105, … (누적 5·(L−1)L/2) 24시간에 차는 최대 골드 = 광산 레벨 × 200

여기서는 상위 20명의 직업 레벨 합이 전부입니다 — 인원을 더 늘려도 21등부터는 안 세어집니다. 레벨 30짜리 스무 명이면 합 600, 광산 16레벨, 하루 3,200골드입니다. 24시간이 지나면 더 안 쌓이니 하루에 한 번은 받아 가야 합니다.

주점 — 용병을 뽑을 때

주점 레벨은 초빙 포인트를 바꿉니다. 이 포인트가 뽑히는 용병의 능력치를 정합니다.

포인트 = (기본값) + 주점 레벨 + Rand(2~3) if (RandSuccess100(10)) 포인트 += Rand(주점 레벨) // 10% 확률로 0 ~ 레벨−1 화면의 «최대» = 주점 레벨 + 3

주점 레벨이 그대로 더해지고, 10% 확률로 한 번 더 0~(레벨−1) 만큼 붙습니다. 능력치 자체는 종족의 기준값을 CreateRandomValue 로 흔든 값이라, 범위는 종족 표에 적어 뒀습니다.

상점 — 레벨이 곧 파는 물건의 레벨

무기·방어구 상점은 레벨마다 재고가 통째로 갈립니다. 대체로 레벨 1칸 = 아이템 레벨 1칸 이고, 출발점은 도시마다 다릅니다 — 실바드 타운은 Lv0부터, 하스포지는 Lv9부터 시작합니다. 도시 시설 표에 레벨별로 무엇을 파는지 적혀 있습니다.

7직업이 실제로 하는 일

직업 레벨을 코드가 참조하는 곳을 전수로 찾았습니다. 특수 분기가 있는 직업은 셋뿐입니다. 나머지 60여 직업은 스탯 보너스·스킬·장착 가능 무기로만 갈립니다.

직업코드가 쓰는 곳통찰 보너스
도적금고 발견·해제, 함정 96건, 전투주 +4 / 부 +2
레인저함정 109건, 전투주 +4 / 부 +2
현자이벤트 등장 조건, 함정 28건주 +10 / 부 +5

여러 직업을 키우면 왜 급격히 느려지나

필요 경험치 = (직업 레벨 + 1)2.5 × 14 × (1 + (expLevel − 1) / 4) // 직업마다 다른 계수 × 1.05(다른 직업 레벨의 합)

다른 직업 레벨 1점마다 필요 경험치가 5%씩 복리로 붙습니다. 합이 20이면 2.7배, 50이면 11.5배, 100이면 131배, 150이면 1,521배입니다. 보조로 조금씩 올려 둔 직업이 주직업의 성장을 그대로 눌러 버립니다.

직업 계수도 큽니다 — 모험가 ×1.00, 초급 직업 ×1.25, 도둑 ×2.75(최고), 레인저 ×2.50. 클래스 표에 전부 적어 뒀습니다.

Character.GetExpToNextLevel · Job.NeedNextExp · Character.SumOtherJobLevels

전투에서는 ExecuteBattle 안에서 도적 레벨 + 레인저 레벨 + 통찰을 함께 더해 씁니다 — 둘 다 기여합니다. 현자는 통찰 보너스가 압도적이고 단검·검·활·창·지팡이를 전부 듭니다.

8확인하지 못한 것

  • 게시판이 하루에 몇 칸을 뽑는지 — TownAverageQuestCount 가 100/30으로 갈리는 플래그의 정체
  • 대장간 강화가 한 번에 몇 단계를 굴리는지 — clamp(n+1, 3, 15) 인데 n 의 출처가 비동기 코드 안에 있습니다
  • 보물금고에서 나오는 아이템 일부 — 마스터 데이터에 없는 것이 있습니다

이 문서는 클라이언트 판번호 6061 에서 뽑았습니다 (세이브의 GameData.currentVersion 과 같은 값). 게임이 업데이트되면 낡습니다 — 퀘스트 색인에 세이브를 넣으면 판번호가 달라졌는지 알려 줍니다.
