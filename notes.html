게임이 안 알려주는 계산식

전부 설치된 APK에서 직접 확인한 것입니다. 마스터 데이터는 Addressables 번들에서, 계산식은 libil2cpp.so 를 디스어셈블해서 읽었습니다. 추측이 섞인 곳은 그렇다고 적어 뒀습니다.

1평판

요구 평판은 부호에 따라 방향이 반대입니다. 양수는 «그 값 이상»이라야 뜨는 하한이고, 음수는 «그 값 이하»여야 뜨는 상한입니다. 그래서 선행 체인을 하나로 합칠 수 없어, 퀘스트 색인에서는 ▲ 한 번은 올려야 하는 평판과 ▼ 한 번은 내려가야 하는 평판을 따로 계산합니다.

평판이 오르다 멈추는 이유

퀘스트 레벨 = master.level + Min(addLevel, master.maxAddLevel) 평판 상한 = 5 × (퀘스트 레벨 − TownMaster.maxReputationLevel + 1) // 최소 5 if (평판 상한 >= 현재 평판) 현재 평판 += master.reputation // 최대 99

낮은 레벨 퀘스트를 아무리 반복해도 평판이 어느 선에서 멈추는 이유입니다. 천장이 5 단위로 올라갑니다.

Town.MaxReputation · Town.ApplyReputationChange

2게시판 — 칸을 다투지 않습니다

게시판에는 «칸» 이 없습니다. 퀘스트마다 자기 카운터를 하나씩 들고 있고, 그 카운터가 0 이 되면 뜹니다. 서로 자리를 뺏지 않습니다 — 게시판에 이미 잔뜩 걸려 있어도 새 퀘스트가 뜨는 데 아무 지장이 없습니다.

갱신할 때 도는 것은 아직 안 떠 있는 퀘스트뿐입니다. 이미 게시된 것(Status = NotAccepted)은 아예 건드리지 않습니다. 그래서 «지우고 새로 채우기» 가 아니라 그대로 두고 추가만 하는 쪽입니다.

for (안 떠 있는 퀘스트 하나씩) { if (조건·빈도 판정 실패) continue; // 카운터도 안 줄어든다 if (!isAddOnly) 카운터 -= 1; if (카운터 ≤ 0) Quest.Start() // 게시판에 뜬다 }

내려가는 건 기한이 지날 때뿐

게시된 퀘스트는 deadline(분+시+일)이 지나야 내려갑니다. 그때 카운터가 questSpawnInterval 로 리셋되어 처음부터 다시 셉니다 — 깨서 Finish() 했을 때도 똑같습니다. 그러니 안 받을 퀘스트를 게시판에 오래 묵혀 두는 것 자체는 손해가 아닙니다. 다만 기한이 지나 내려가면 그 퀘스트는 카운터를 처음부터 다시 채워야 합니다.

기한은 퀘스트마다 다릅니다 — deadlineDays·Hours·Minutes 세 칸을 합친 값이고, 1,364건에 145가지가 있습니다. 2시간에서 12일까지, 중앙값은 1.7일입니다. 레벨과는 거의 무관합니다(어느 레벨대나 중앙값 1.4~1.8일).

1회성 퀘스트는 기한이 유난히 짧습니다. 주기 99(1회성) 266건의 중앙값이 18시간이고 81%가 하루 안에 내려갑니다. 반복 퀘스트는 10%뿐입니다. 어렵게 띄운 1회성을 하루 넘겨 두면 다시 카운터를 처음부터 채워야 합니다 — 퀘스트 색인의 각 퀘스트에 «게시판 유효기간» 으로 적어 뒀습니다.

수주하고 나면 이 시계는 멈춥니다. 기한 검사는 게시 중(NotAccepted) 일 때만 돌고, 수주해서 InProgress 가 되면 기한으로 실패하는 길이 없습니다.

카운터가 줄려면 빈도 판정을 통과해야 합니다

3금고 — 발견과 해제

살아 있는 파티원을 차례로 굴려 한 명만 통과하면 성공입니다. 발견과 해제 두 판정을 모두 넘겨야 물건을 얻고, 해제 난이도가 0이면 해제 판정은 건너뜁니다.

목표 = 퀘스트 레벨 + 금고값(발견값 또는 해제 난이도) 내 값 = 2d6(10 이상이면 다시 굴려 더함) + 도적 직업레벨 + 리더 보너스 + 통찰력/3 성공 = 내 값 >= 목표 + 2d6
함정이 둘 있습니다.
· 통찰력 보너스는 «도적레벨 + 리더보너스»가 1 이상일 때만 붙습니다. 도적을 안 키운 파티원은 통찰이 아무리 높아도 0으로 굴립니다.
· 첫 2d6이 1+1이면 −100(대실패) 입니다. 1/36은 어떤 능력치로도 못 막습니다 — 한 명 기준 천장이 97.22% 입니다.

5강화 — 무기의 추가 공격, 방어구의 회피

두 옵션은 마스터 데이터에 없습니다. 강화(craft)가 굴립니다. 그리고 결정적인 조건이 있습니다 — 한 번에 5단계 이상 강화될 때만 도는 블록 안에만 들어 있습니다.

옵션일반 무기마법 무기
추가 공격5%15%
후열 포함15%25%
전체 공격5%15%
후열 포함과 전체 공격은 추가 공격이 먼저 붙어야만 굴립니다. 추가 공격 판정에 실패하면 두 줄을 통째로 건너뜁니다.

상점에서 살 때 붙는 등급

if RandSuccess100(20) craft = 1 // 20% if RandSuccess100(5) craft = 2 // 5% if RandSuccess100(1) craft = 3 // 1% if RandSuccess(1,1000) craft = Rand(3,6) // 0.1% → +3·+4·+5 RunCraft(craft)

+5로 나올 확률이 0.1% × ⅓ = 약 1/3000 입니다. 곱하면 상점 무기에 추가 공격이 붙을 확률은 약 1/60,000, 전체 공격은 약 1/1,200,000 입니다. 돈을 아무리 모아도 상점으로는 사실상 불가능합니다.

대장간에서 다이아로 강화할 때

상점과는 완전히 다른 사다리입니다. 그리고 시작점이 «대장간 레벨 − 장비 레벨» 이라, 낮은 레벨 장비일수록 한 번에 훨씬 많이 굴려집니다.

n = 대장간 레벨 − 장비 레벨 p = 50 while (RandSuccess(p)) { n += 1; p -= 5 } // 50% → 45% → 40% → … craftIndex = clamp(n + 1, 3, 15) RunCraft(craftIndex)

최소 3단계는 보장되고, 첫 성공이 50%라 잘 늘어납니다. 대장간 29 기준으로 다이아 한 번에 붙을 확률입니다.

활만 예외입니다

강화 단계마다 도는 5% 관문을 통과하면, Weapon.Kind.Bow 는 5단계 조건 없이 추가 공격이 확정으로 붙습니다.

방어구는 규칙이 다릅니다 — 단계마다 «무엇이 붙는지» 가 정해져 있습니다

무기는 5단계 블록 하나에 몰려 있었지만, 방어구는 단계 번호 자체가 조건입니다. RunCraft(n) 은 Craft(i) 를 i = n, n−1, …, 1 로 n번 부릅니다. 그래서 «3단계 강화» 는 i=3, 2, 1 을 한 번씩 지나갑니다.

회피는 «확률» 이 아니라 «2단계 이상이면 붙는 것» 입니다. 무기의 추가 공격처럼 5% 관문 뒤에 숨어 있지 않습니다. 2단계 이상으로 강화되면 회피 +1~2 가 반드시 붙고, 5% 묶음에 걸리면 거기서 +1 이 더 붙습니다. 옷은 1·3 단계에서도 붙어서, 3단계 강화면 회피가 세 번(i=3·2·1) 들어갑니다.

거꾸로, 1단계 강화로는 회피가 5%로만 붙습니다 — 상점 무기·방어구가 대부분 여기입니다(20%로 +1, 5%로 +2). 대장간 다이아 강화는 최소 3단계가 보장되므로 회피는 사실상 딸려 옵니다.

부적은 방어력이 0 이라 위 표의 첫 두 줄(5% 묶음 포함)을 통째로 건너뜁니다. 대신 i=2 의 회피와 매 단계 민첩은 그대로 받습니다.

Armor.Craft · Equipment.RunCraft · ArmorMaster.Ability.isMagic

몇 단계가 걸리나 — 대장간 레벨이 정합니다

강화가 «몇 단계» 로 들어가는지는 위의 두 옵션을 가르는 가장 중요한 값입니다 (무기의 추가 공격은 5단계 이상, 방어구의 회피는 2단계 이상). 그 수는 이렇게 정해집니다.

강화석 1개 소비 n = 대장간 레벨 − 장비 레벨 p = 50 while RandSuccess(p): n += 1; p −= 5 // 50 · 45 · 40 … 5 % 단계 = clamp(n + 1, 3, 15)

보너스 굴림은 50%로 시작해 성공할 때마다 5%p씩 낮아집니다. 그래서 보너스는 0회가 절반이고, 기댓값은 0.86회 입니다.

확률50%27.5%13.5%5.9%2.2%0.9%

현실적인 길

제작등급 5 이상으로 떨어지는 드랍은 전체 데이터에 10종뿐입니다 — 도감의 «+5강 이상 드랍» 태그로 걸러집니다. 가장 높은 건 좀비 워리어의 녹슨 검(+9) 인데 Lv2 무기라 실전성은 없습니다.

그보다 두 옵션이 처음부터 박혀 있는 무기가 39종 있고, 거의 전부 퀘스트 금고에서 나옵니다. 도감 아이템 탭의 «전체 공격»(24) / «추가 공격»(15) 체크박스로 찾으세요.

마법 속성은 강화로 못 붙입니다. Enhancement.Kind.IsMagic(254) 가 enum에 있지만 Weapon.Craft 가 그걸 만드는 자리는 없습니다(생성 지점 28곳 전수 확인). 마스터 데이터의 isMagic 플래그가 유일한 경로라, 마법 속성 무기는 처음부터 그런 것을 구해야 합니다.

은퇴 — 골드와 경험치가 여기서 나온다

은퇴시킨 용병은 사라지지 않고 둘을 계속 벌어 줍니다. 은퇴 정원은 숙소 레벨 × 5 입니다.

① 경험치 보너스

보너스% = min( 조건을 통과한 은퇴자 수 × 5, 100 ) 조건: 은퇴자의 최고 직업 레벨 > 경험치를 받는 캐릭터의 레벨

스무 명이면 +100% 로 상한에 닿습니다. 그 위로는 아무 소용이 없습니다 — 다만 «내 레벨보다 높은» 은퇴자여야 세어지므로, 주력이 성장할수록 조건을 통과하는 인원이 줄어듭니다. 모험 경험치(AddAdventureExp)에 붙습니다.

② 광산 골드

광산 레벨 = 은퇴자를 최고 직업 레벨 순으로 상위 20명만 골라 그 합을 계단에 대입 계단: 5, 15, 30, 50, 75, 105, … (누적 5·(L−1)L/2) 24시간에 차는 최대 골드 = 광산 레벨 × 200

주점 — 용병을 뽑을 때

주점 레벨은 초빙 포인트를 바꿉니다. 화면에 별처럼 뜨는 그 숫자입니다.

포인트 = Rand(3) // 0~2 + 주점 레벨 + Rand(1~3) // 갈래에 따라 0~2 if (RandSuccess100(10)) 포인트 += Rand(주점 레벨) // 10% 로 0 ~ 레벨−1 실제 최대 = 주점 레벨 × 2 + 3 화면의 «최대» = 주점 레벨 + 3
화면에 뜨는 «최대»가 진짜 최대가 아닙니다. 표시는 주점 레벨 + 3 인데 10% 주사위가 터지면 주점 레벨 × 2 + 3 까지 갑니다. 6레벨 주점이면 표시는 9인데 실제로는 15 까지 나옵니다.

포인트와 능력치는 서로 다른 주사위입니다

이 둘을 섞어 생각하면 헷갈립니다. 용병을 뽑을 때 주사위가 두 번, 서로 무관하게 굴러갑니다.

주점을 올려도 «민첩 7~11» 같은 범위는 안 바뀝니다. 그 범위는 종족이 정합니다 — 풋워커 남자의 민첩 기준값이 9라서 7~11 입니다. 주점 레벨이 바꾸는 것은 포인트뿐입니다.

예 — 주점 6레벨

Rand(3) → 0 ~ 2 + 주점 레벨 → +6 (언제나) + Rand(1~3) → 0 ~ 2 ─────────────────── 6 ~ 10 ← 여기까지가 «보통» 10% 로 한 번 더: + Rand(6) → 0 ~ 5 ─────────────────── 6 ~ 15 ← 실제 최대 15, 화면 표시는 9

능력치 자체의 범위는 종족 표의 괄호에 적혀 있습니다.

상점 — 레벨이 곧 파는 물건의 레벨

무기·방어구 상점은 레벨마다 재고가 통째로 갈립니다. 대체로 레벨 1칸 = 아이템 레벨 1칸 이고, 출발점은 도시마다 다릅니다 — 실바드 타운은 Lv0부터, 하스포지는 Lv9부터 시작합니다. 도시 시설 표에 레벨별로 무엇을 파는지 적혀 있습니다.

7직업이 실제로 하는 일

직업 레벨을 코드가 참조하는 곳을 전수로 찾았습니다. 특수 분기가 있는 직업은 셋뿐입니다. 나머지 60여 직업은 스탯 보너스·스킬·장착 가능 무기로만 갈립니다.

직업코드가 쓰는 곳통찰 보너스
도적금고 발견·해제, 함정 96건, 전투주 +4 / 부 +2
레인저함정 109건, 전투주 +4 / 부 +2
현자이벤트 등장 조건, 함정 28건주 +10 / 부 +5

주/부 보너스는 «레벨 × 보너스 ÷ 10, 올림» 입니다

클래스 표의 «주 보너스 / 부 보너스» 숫자는 그대로 더해지는 값이 아닙니다. Character.AddJobBonuses 가 이렇게 씁니다:

직업 몫 = ⌈주직업레벨 × 주보너스 ÷ 10⌉ + ⌈Σ(부직업레벨 × 부보너스) ÷ 10⌉

두 가지가 중요합니다. 주직업은 하나만 세지만(Job.isCurrent 가 켜진 것 — 레벨 1등이 아닙니다), 부직업은 가진 것 전부를 합칩니다. 그래서 부 보너스가 있는 직업을 여럿 올려 두면 합이 꽤 커집니다.

예계산회피값
도둑 30을 주직업으로⌈30×7÷10⌉21
도둑 30을 부직업으로⌈30×3÷10⌉9
부직업에 도둑30·검술사30·마검사30⌈30×(3+2+2)÷10⌉21
회피 보너스가 있는 직업은 36종 중 12종뿐입니다 — 도둑(주7/부3)이 압도적이고, 마도병·마검사·숨은 칼날의 궁사·검술사·베테랑 파이터가 4/2, 나머지는 2/1 이하입니다. 회피탱을 만들 생각이면 도둑을 주직업으로 두는 것이 가장 크고, 나머지 열한 직업은 부직업으로 쌓을 수 있습니다.
현자와 모험가는 이 «다른 직업 레벨 합» 에 안 들어갑니다. Character.SumOtherJobLevels 의 술어가 Job.Kind 202(현자)와 0(모험가)를 빼고 셉니다. 그래서 이 둘은 아무리 올려도 다른 직업의 경험치를 비싸게 만들지 않습니다 — 경유 직업으로 놔둬도 손해가 없습니다.

여러 직업을 키우면 왜 급격히 느려지나

필요 경험치 = (직업 레벨 + 1)2.5 × 14 × (1 + (expLevel − 1) / 4) // 직업마다 다른 계수 × 1.05(다른 직업 레벨의 합)

다른 직업 레벨 1점마다 필요 경험치가 5%씩 복리로 붙습니다. 합이 20이면 2.7배, 50이면 11.5배, 100이면 131배, 150이면 1,521배입니다. 보조로 조금씩 올려 둔 직업이 주직업의 성장을 그대로 눌러 버립니다.

직업 계수도 큽니다 — 모험가 ×1.00, 초급 직업 ×1.25, 도둑 ×2.75(최고), 레인저 ×2.50. 클래스 표에 전부 적어 뒀습니다.

Character.GetExpToNextLevel · Job.NeedNextExp · Character.SumOtherJobLevels

전투에서는 ExecuteBattle 안에서 도적 레벨 + 레인저 레벨 + 통찰을 함께 더해 씁니다 — 둘 다 기여합니다. 현자는 통찰 보너스가 압도적이고 단검·검·활·창·지팡이를 전부 듭니다.

8명중과 회피 — 몬스터는 주사위를 안 굴립니다

맞느냐 빗나가느냐는 이 한 줄입니다. 명중 − 회피 ≥ −1 이면 맞습니다. 뒤집으면 회피가 명중보다 2 이상 크면 무조건 빗나갑니다. 확률이 아니라 값 비교입니다.

그런데 몬스터 쪽에는 주사위가 없습니다. 캐릭터만 2d6 을 굴립니다. 그래서 «회피가 얼마면 다 피하나» 에 정확한 답이 나옵니다.

몬스터 (고정값) 명중 = 몬스터 레벨 + hitPoint + 7 + 스폰 레벨보정 회피 = 몬스터 레벨 + avoidPoint + ⌊민첩/3⌋ + 7 − 2 (+2 비행) 캐릭터 (굴림) 명중 = 2d6 + ⌊CreateRandomValue(재주)/3⌋ + 명중값 + 지형 + 상태 회피 = 2d6 + ⌊CreateRandomValue(민첩)/3⌋ + 회피값 + 지형 + 상태

여기 7 은 Util.Dice2DAvg 입니다 — 2d6 의 기댓값을 몬스터에게 상수로 준 것입니다. 그래서 몬스터는 «평균만큼 굴린 셈» 으로 고정됩니다.

그래서 회피가 얼마면 다 피하나

2d6 의 최솟값이 2 이므로, 아래를 채우면 그 몬스터의 물리 공격은 한 대도 안 맞습니다.

회피값 + ⌊CreateRandomValue(민첩)의 최솟값/3⌋ + 지형 ≥ 몬스터 명중

이 몫이 민첩에 따라 달라집니다 — 민첩이 낮으면 회피값이 더 필요합니다.

물리 무효는 «마법 무기» 로 뚫립니다

invalidPhysics 가 36종 있는데, 무효 판정이 이렇게 돼 있습니다:

if (대상.InvalidPhysics() && !공격.isMagicAttack) → 무효

즉 공격이 «마법 공격» 으로 표시되면 그대로 통합니다. 그 표시는 BattleCreature.IsUseMagicWeapon() 이 정합니다:

무기가 없으면 → 아니오 주직업이 마검사(Job.Kind 29) 이고 단검을 들었으면 → 예 // 부직업이면 안 된다 그 외에는 Weapon.IsMagic() — 무기 마스터의 ability.isMagic (강화로 붙는 IsMagic(254) 도 세지만, 강화는 그걸 만들지 않습니다) 그리고 EffectOnCreature 41 이 걸려 있으면 무조건 예
마법 무기는 446종 중 68종(15%)입니다. 활이 12종, 단검이 8종 있습니다 — 실버 활(Lv5) · 엘프 활(7) · 지구결속 활(12) · 아케인 연마 활(16) · 프리즈 아이(17) · 기원의 활(22) · 넝쿨 묶은 활(23) · 모래거울 활(24) · 지문의 현궁(25) · 라이프드레인보우(28) · 명천궁(30) · 불타는 활(34). 도감 아이템 줄에 «마법» 표로 붙여 뒀습니다.
마검사는 «주직업» 일 때만 통합니다. IsUseMagicWeapon() 이 보는 건 Character.MainJob() 이고, 그건 Job.isCurrent 가 켜진 직업 — 게임에서 지금 지정해 둔 직업 하나뿐입니다. 마검사를 부직업으로 달아 두면 단검을 들어도 물리 공격 그대로입니다. 그리고 마검사가 들 수 있는 무기는 단검뿐이라(최대 레벨 30), 다른 무기로는 이 길이 없습니다.

강화로는 마법 속성을 못 붙입니다. 처음부터 마법인 무기를 구해야 합니다 — 물리 무효 몬스터가 36종이나 되니, 파티에 마법 무기를 하나는 끼워 두는 편이 안전합니다.

후퇴 — 리더의 성격만 봅니다

후퇴는 리더 한 명의 성격으로 정해집니다. 나머지 파티원의 성격은 여기에 아무 영향이 없습니다. 방식은 «점수 적립»입니다 — 사건이 하나 끝날 때마다 파티에 후퇴 점수가 쌓이고, 그 합이 기준점에 닿는 순간 되돌아섭니다.

A = 살아 있는 인원   N = 전체 인원 무모한 → int.MaxValue // 사실상 없음 — 전멸까지 안 돌아선다 이기적 → N == 1 ? 30 : 24 사교적 → N < 2 ? 2 : A × 4 신중한 → A > 1 ? A × 2 : 3 합리적 → A ≥ 2 ? A × 3 + 2 : 3 신경질적 → A == 1 ? 4 : A × 3 감정적 → Rand(7, 30) // 판정할 때마다 새로 굴린다 리더가 죽어 있으면 → 0 // 다음 사건에서 바로 돌아선다
기준점은 살아 있는 인원에 비례합니다. 한 명 죽으면 기준점 자체가 내려가서, 남은 점수로도 곧바로 넘길 수 있습니다 — 무너지기 시작하면 가속이 붙습니다. 무모한 리더만 이 사다리 밖에 있습니다.

회복 마법을 언제 쓰는가

회복 주문의 설명문에 «시전자의 성격에 따라 사용 타이밍이 달라집니다» 라고 적혀 있는 그 부분입니다. 시전자의 성격이 기준선을 올립니다.

T = min(스킬의 healTiming + 성격 보정, 8) 신중한 +2  ·  합리적 +1  ·  신경질적 +1  ·  나머지 +0 대상으로 고른다 ⇔ HP ≤ 최대 HP × T / 10 또는 HP == 1 또는 잃은 HP > (마법력 + (최소회복+최대회복)/2) − 2

게임 안의 모든 스킬이 healTiming = 5 입니다 (152건 전수). 그래서 실질적으로 성격만 남습니다 — 신중한 70% · 합리적/신경질적 60% · 나머지 50%. 상한 8(80%)에는 어떤 조합으로도 닿지 않습니다.

힐러는 신중한이 가장 빠릅니다. 다른 성격의 힐러는 HP가 절반으로 떨어질 때까지 기다립니다 — 한 방에 절반 넘게 맞는 구간에서는 그 차이가 그대로 사망으로 이어집니다. 마지막 줄(«잃은 HP가 회복량보다 크면») 덕분에 최대 HP가 큰 캐릭터는 기준선 위에서도 힐을 받습니다.

10근접은 왜 맞아죽는가 — 구조입니다

「방어를 올려도, 회복을 붙여도 근접이 죽는다」 는 느낌은 맞습니다. 방어로는 못 버티게 돼 있습니다. 세 줄이면 끝납니다.

몬스터 공격력 = 3L + (L>4 ? 2L−8 : 0) + 조정 // 주사위 없음 — 고정값 피해 = 공격력 − ⌊대상 방어 ÷ 2⌋, 최소 1 방어구 방어 = 2 × 장비 레벨
방어는 절반만 깎습니다. 그런데 몬스터 공격력은 레벨에 5L−8 로 붙습니다. 방어를 최대로 껴도 깎이는 몫이 공격력의 절반도 안 됩니다. 레벨이 오를수록 격차가 벌어집니다 — 좁혀지지 않습니다.

모험가 주직업이 나쁘지 않은 이유

방어구 다섯 부위를 전부 끼는 직업은 모험가 하나뿐입니다. 다만 방어만 보면 중도사·가드도 129 를 찍습니다(갑옷+투구+방패) — 부적은 방어가 0 이고, 의복은 갑옷보다 낮아서 자리가 늘어도 방어는 안 늘어납니다. 모험가의 값은 다른 데 있습니다.

  • 최대 레벨 31 — 지금 서비스에서 유일하게 30 을 넘습니다.
  • 부적 자리 — 방어는 0 이지만 회피 +5(세라믹스틸 오멘워드 탈리스만 Lv27) 같은 것이 붙습니다. 회피 빌드에서는 이 한 자리가 큽니다.
  • 경험치 지수에 안 들어갑니다 — 현자와 모험가만 1.05^(다른 직업 레벨 합) 의 지수에서 빠집니다. 부직업을 여럿 키우는 빌드일수록 주직업으로 값이 큽니다 — 아무리 올려도 나머지를 비싸게 만들지 않습니다.
  • 모든 무기를 씁니다.

대신 주직업 생명점 보너스가 2 로 낮습니다(무장병 13 · 중도사 14). 31레벨을 다 채워도 +7 뿐입니다. 그래도 위 표대로 HP 는 부직업 쪽이 대부분이라 손해가 작고, 대신 투구·부적 자리와 싼 경험치를 얻습니다.

회복으로도 못 메웁니다

가장 센 회복이 바이탈라이즈 28~48(단일 · Lv30 · MP9), 전체 회복은 살바 16~24 입니다. Lv30 몬스터 한 대가 78~106 이니 한 대 맞은 걸 되돌리는 데 두세 번이 듭니다. 몬스터는 매 턴 때리고, 여럿이 때립니다.

그래서 회피뿐입니다

회피는 확률이 아니라 결정입니다 — 명중 − 회피 ≥ −1 이면 맞고, 아니면 안 맞습니다. 몬스터의 명중은 주사위 없이 고정이라, 회피값이 충분하면 물리 공격은 100% 안 맞습니다(§8). 방어는 «덜 맞기» 인데 회피는 «안 맞기» 라, 격차가 벌어지는 판에서는 후자만 답이 됩니다.

다만 회피는 물리 전용입니다. AvoidRate 는 PhysicsAttack 에서만 불립니다. 마법과 광역 마법은 회피탱도 그대로 맞습니다 — 그쪽은 마법 방어와 HP 로 버텨야 합니다.
